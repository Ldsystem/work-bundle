# Root Plan v1 semantic contract

The current `root-plan` family is schema-owned YAML. Supply semantic YAML to `write-plan`; do not add front matter, choose a filename, or repeat injected `artifact_type`, `schema_version`, `id`, `goal`, `purpose`, `component`, `version`, `source_spec_id`, `status`, `date_created`, or `last_updated` fields.

The semantic input requires `source_coverage`, `authority`, `strategy`, `phase_index`, `dependency_graph`, `risks`, `validation_strategy`, `completion_criteria`, `knowledge_base_update`, `semantic_loop`, and `execution_workspace`. Each coverage row names a stable source ID, obligation kind, non-empty phase/task ownership, and validation IDs when validation-bearing. Cite the verified specification by `source_spec_id`; presentation paths such as `.work-bundle/orchestration/spec/active/...` are not authority.

Decompose without optimizing task or phase cardinality. Every authoritative production path needs one production owner; reject helper-only allocation. Responsibility ownership does not set task granularity: one owner may receive multiple dependency-ordered bounded execution packets, including ordered reuse of a production file. Start from the accepted outcome and capable local oracle. Choose one coherent task when splitting would leave an unstable or unreviewable intermediate result; choose ordered packets when each predecessor produces a usable accepted intermediate result; choose contract-decoupled parallel packets only against a sufficiently stable existing or task-produced boundary. Keep a coherent mechanical increment with one owner, oracle, and repair frontier together. Split independently owned entry points only when current repository evidence proves distinct seams. Bound expected total orchestration cost across execution, context, coordination, validation, review, and repair; weigh demonstrated reuse, feasibility, and stability. Line, token, source-ID, file, and task counts are diagnostic clues, not qualification thresholds. Create a phase only for an actual barrier or convergence boundary; reject speculative splits. When a task is materially under-decomposed, return to the plan and reslice only the affected unaccepted authority region; do not repeatedly enlarge it.

Assign parallel tasks only when dependencies are satisfied and write scopes are disjoint. Unsafe parallelization is explicitly blocked by dependency or scope evidence. Overlapping write paths require strict dependency order and the predecessor's canonical accepted result before successor execution. Contract-decoupled work names a common contract group, barrier participants, readiness, release condition, convergence owner, and post-barrier convergence task when those constructs apply. Use local contract tests where they provide capable oracles at a genuine stable seam, then joint validation at convergence; work sequentially while the seam is unsettled. An existing stable interface may suffice; no separate contract artifact is compulsory.

Every task declares `evidence_capability`. Use `mapped` with a lightest-capable task-local oracle for validation-bearing obligations, or `no_validation_bearing_obligation` with a concrete reason.

Run canonical static task admission for every task before initial semantic review. Structural success cannot establish source-ID coverage, packet coherence, appropriate decomposition, capable validation, or executability. A distinct reviewer compares the complete stored tree directly with the verified specification and current source evidence, assesses whether packets are bounded and genuinely separable, and provides advisory `accept`, `repair`, or `blocked` findings. The controller/orchestrator assesses that advice and owns plan qualification. After a bounded phase or task repair, rerun admission for the affected task/dependency and global graph/ownership invariants, then review each complete repaired artifact with its applicable root/phase authority, dependency closure, interfaces, and allocated obligations. This uses the existing full-plan or affected-closure review, with no extra per-task invocation. Preserve unaffected qualification; reviewing only changed fields remains insufficient.

`write-plan`, `write-phase`, and `write-task` update an existing active identity at its canonical path. Use `amend-task` for a bounded repair: it applies strict structural, dependency, allocated-obligation, ownership, binding, and candidate-compilation checks before mutation, updates the canonical task in place, refreshes only its compiled brief, and reports mechanically affected tasks for controller assessment. Use a new identity only for a genuinely distinct plan, phase, or task, never to retain intermediate repair versions. Return a verified root plan to `draft` before changing phase or task content. Initial or global qualification reviews the complete tree; a bounded repair qualifies only its affected semantic authority closure and preserves unaffected qualified regions.

The canonical global semantic plan projection is `canonical-yaml-plan-tree-v1`. Task implementation review uses `canonical-task-authority-v1`. Its specification projection contains the exact requirement/decision records named by the task, its transitive dependencies, mechanically connected ownership/interface peers, and global decision IDs declared by root authority or strategy. Its plan projection contains applicable global root policy, filtered coverage/validation/dependency allocation, applicable phase policy and membership, the complete task and transitive dependency tasks, their current accepted results, and mechanically shared ownership/interface records. Unreferenced specification prose, unrelated source records, and unrelated phase membership are not identity-bearing. Referenced semantics and genuinely global authority remain identity-bearing. Current plan and specification revisions do not consume post-execution review rounds.
